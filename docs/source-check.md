# 书源批量校验（校验书源）

对齐 Legado 原版 `CheckSource` / `CheckSourceService`（见 `model/CheckSource.kt`、`service/CheckSourceService.kt`）。

## 语义

单个书源按顺序校验：

1. **域名可达**（可关）：源地址必须是 http(s)，否则记 `域名失效`；NWConnection 探测（https→443、http→80，
   1.6s 上限；原版一律 80，这里对 https 更准）。
2. **搜索**：`getCheckKeyword` 取关键词（`ruleSearch.checkKeyWord` 是普通词才用，否则用设置关键词，默认「我的」）。
   `searchUrl` 空 → `搜索链接规则为空`（原版不计失效）；搜索为空 → `搜索失效`；否则继续校验第一本书。
3. **发现**：`exploreUrl` 非空才校验；`exploreKinds` 无可用网址 → `发现规则为空`（原版不计失效）；
   发现页为空 → `发现失效`；否则校验第一本书（目录/正文失败前缀是「发现」）。
4. **详情 → 目录 → 正文**：目录空 → `{搜索|发现}目录失效`；正文空 → `{搜索|发现}正文失效`；
   成功时清掉两类旧分组。

收尾：存在失效分组（含「失效」或等于「校验超时」）→ 整体失败，消息为分组名；否则 `校验成功`。
失败按设置把 `// Error: 原因` 写进书源注释（成功时清掉旧的）；耗时毫秒写入 `respondTime`（原版同名字段）。
超时（默认 180s，可设）→ `校验超时`；脚本异常 → `js失效`；其它错误 → `网站失效`。
用户中途停止 → 结果标记「已取消」，**不改写**书源（对应原版 `ensureActive` 中断）。

分组规则与原版一致：`[,;，；]` 分隔、并集去重、逗号回写；`invalidGroupNames` 只算含「失效」或「校验超时」的组。

## 入口

- 书源页右上菜单：`校验全部书源` / `校验启用中的书源`；单个书源长按：`校验此书源`。
- 校验页：关键词、超时、六个开关（域名/搜索/发现/详情/目录/正文，依赖关系同原版设置弹窗）、
  「失败写入书源注释」、设置摘要、逐源结果（状态/消息/分组/耗时）、进度、停止、完成摘要。
  设置记忆在 `reader.source.check.*`（UserDefaults）。

## 命令行 / CI

```
SourceTest --check-batch <sources.json> [关键词] [超时秒] [并发] [数量上限]
```
- 跳过禁用与「魔丸」；打印逐源结果、`BATCH SUMMARY` 与失效分组汇总；退出码 0（源失效属数据，不是构建失败）。
- `source-test.yml`：新增 `batch` 输入（离线也可跑，会自行下载 XIU2/Yuedu 公开书源，取前 12 个）。
- `user-source-test.yml`：新增 `check` 输入，对上传的书源文件跑批量校验。

## 验证

- `SourceCheckRegression`（离线注入钩子，35+ 断言）：分组/注释/关键词、各步分组与消息、
  超时、取消不改写、发现分支、开关、`bookSourceType=3`、域名、并发上限与进度回调。
  注册进 `Regression.swift`（CI `--regression`，共 1153 项）。
- 真实网络：CI 批量校验公开书源 12 个（`source-test` run 38931552360）：`成功 2 / 失败 10`，
  失效分组汇总 `发现失效=4 搜索失效=7 网站失效=3`，与这些源的真实陈旧状态一致。
- App 构建：Build run 38931721025（IPA `LegadoiOS-unsigned.ipa`）。

## 未做 / 边界

- 未做真机目视（校验页观感、停止交互、实机批量跑）；未做 UI 自动化（需合成书源 + 本地 HTTP 服务）。
- 原版校验完成后会自动把书源列表筛选到「失效」，本应用书源列表暂无筛选框，未做。
- `respondTime` 是本次校验耗时（原版是网络步骤耗时），列表里按需显示「响应 Nms」。
