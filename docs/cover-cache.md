# 封面本地缓存（换网络 / 开 VPN 也显示得出来）

## 现象

书架上的封面有时会消失：开了 VPN（或换了网络出口）之后，部分书源的封面地址直接请求失败，
书架就只剩占位图。用户以为「封面本来就存在本机上」，其实并没有。

## 原因

原来的封面加载走系统的 `AsyncImage`：

- App 自己**不落盘**，只依赖系统 URLCache（内存为主，磁盘缓存由服务器响应头决定，还会被系统清掉）；
- `AsyncImage` 不带书源的请求头（Referer / UA / Cookie），图床/聚合站常按请求头或出口 IP 拦截，
  VPN 换了出口 IP 就更容易被拒；
- 请求失败就直接显示占位图，之前成功显示过的封面也没有留底。

## 现在的做法

- **本机缓存**：`Sources/Engine/CoverDiskCache.swift`，把下载到的封面原始字节存到
  `Caches/Covers/<地址的 MD5>.img`。`BookCoverImage` 先查缓存，命中就直接显示（不碰网络）；
  没有再下载，下载成功顺手落盘。下次开 App、换网络、开 VPN 都显示得出来。
  单个封面超过 4MB 不落盘；`我的 → 缓存管理 → 网络响应缓存` 可以连同 URLCache 一起清掉。
- **带书源请求头下载**：普通封面（没有 `coverDecodeJs`）改走
  `RemoteCoverLoader.loadPlain`，用 `AnalyzeUrl` 带书源 `header` 发请求，
  解决图床校验 Referer / UA 导致 403 的情况；仍然失败再退回系统请求。
- **解密书源**：`coverDecodeJs` 解密后的字节才是能显示的图，缓存里存的是解密后的结果，
  不用每次启动都重新解密下载。
- **显示尺寸**：缓存里存原始字节，显示时用 ImageIO 按显示尺寸缩放，避免大图占内存。
- **发现页的封面同样走本机缓存**：`DiscoverCoverImage` 先查内存、再查本机磁盘缓存，
  最后才下载（下载仍受「封面并发数」限制，优先带书源请求头）。
  注意：设置里的「缓存有效期（N 天）」管的是**发现数据**（分类 + 书单列表的 JSON，里面带封面地址），
  不是封面图片；封面图片存在 Caches 里，由系统按空间清理，也能在缓存管理里手动清。

## 回归

`Tools/SourceTest/CoverCacheRegression.swift`（纯离线）：缓存路径稳定、不同地址不冲突、
写入读回一致、空数据与超大数据不落盘、清空后读不到且占用为 0。
