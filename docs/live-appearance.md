# Independent glass cards, splash behaviour and preview scope

- ThemeLaunchOverlay has no Skip button; it dismisses itself after 1.2 seconds in production and in the full-screen editor preview. One splash per process, accessibility escape retained. No system LaunchScreen change.
- Shared independentGlassRow gives app-owned settings/list rows separated round glass cards (search/history, sources/login, reader settings/TOC/search, detail categories/TOC/sources, rule editors, font faces, appearance choices, source debug, reader loading/retry). Real covers, reader paper, color swatches, native system controls and web content stay unwrapped. Explicit saved content-card transparent/opaque/off choices are never overwritten.
- Reader settings keeps its real TextKit typography preview (font/size/spacing/margins/paper/justification) as a scroll sample; it is not a simulated complete bottom-justified page or page-turn preview, and reader settings still save immediately.
- Rolled back on request: the pinned per-setting live preview on the eight theme customization subpages was removed, together with ThemeSettingPreview. The customization pages return to their previous structure — settings controls plus the existing bottom summary preview (ThemePreviewCard/LibraryDock) on tab/colors/background/effect/cards, and no preview surface on shelf/cover/launch. The page-level accessibility identifier is restored, which the older CustomTheme suite relies on to detect a pushed subpage.
- Glass still uses iOS26 Liquid Glass with material fallback and solid Reduce Transparency fallback.
- Native focused tests assert that no live-preview surface remains on any of the eight pages, that controls still edit the draft (shelf columns stepper, effect choices/sliders), that the legacy bottom preview still exists, that the splash has no Skip and auto-returns twice, and that independent List rows stay separated and tappable. Offline fixtures only.
